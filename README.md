# Data Source Onboarding & Connector Generation Agent

A simple full-stack app that turns a natural language request like:

> "Connect to our PostgreSQL sales database at db.company.com using username and password authentication"

into a standardized, reusable Python connector — plus a validation report
and onboarding documentation.

## How it works
1. **agent.py** — a simple rule-based "AI agent" that reads the natural
   language request and extracts a structured spec (source type, auth
   method, host, etc.). Keyword/regex based, so no API key is required to
   run the project.
2. **templates.py / generator.py** — fills a standardized Python connector
   template (PostgreSQL, MySQL, SQL Server, or REST API) using the spec.
3. **validator.py** — checks the generated code's syntax (`ast.parse`) and
   runs a simulated connection test (since real credentials usually aren't
   available at generation time).
4. **doc_generator.py** — produces onboarding docs, a code explanation, and
   setup/dependency instructions.
5. **app.py** — FastAPI app tying it all together.
6. **React frontend** — a form to submit requests and a page to view the
   generated code, validation, and docs.

## Running the backend
```bash
cd backend
python3 -m venv venv
source venv/bin/activate      # on Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app:app --reload --port 5001
```
The API runs at `http://localhost:5001` (not 5000 — macOS's AirPlay
Receiver uses port 5000, so this project uses 5001 instead).

Interactive API docs (auto-generated by FastAPI) are available at
`http://localhost:5001/docs` — handy for testing endpoints without curl.

Note: `requirements.txt` only includes what the backend itself needs
(Flask). The generated connector code references `psycopg2`,
`mysql-connector-python`, `pyodbc`, or `requests` — install those
separately only if you actually want to run a *generated* connector
file against a real database/API.

## Running the frontend
```bash
cd frontend
npm install
npm start
```
Opens at `http://localhost:3000` and talks to the backend at port 5001.

## Connecting to a real, existing data source
By default, `validator.py`'s check is *simulated* (it only checks the spec
looks valid, not a real connection). To test against a **real** data source:

1. Install the real drivers (already in `requirements.txt`):
   ```bash
   pip install -r requirements.txt
   ```
   On macOS, `pyodbc` (SQL Server) also needs a system ODBC driver:
   ```bash
   brew install unixodbc
   # then install Microsoft's ODBC driver for SQL Server (see Microsoft's docs
   # for macOS — search "Microsoft ODBC Driver 17 for SQL Server macOS")
   ```
   If you're not testing against SQL Server, you can skip this and just
   remove/comment out `pyodbc` from `requirements.txt`.

2. Generate a connector as usual in the UI.

3. Scroll to the **"Test Real Connection"** section under the results. Enter
   your actual host, port, database, username, and password (or API key for
   REST sources), and click **Test Live Connection**.

4. The backend (`real_connectors.py`) will attempt a real connection using
   the appropriate driver and return `success`, `failed` (with the real
   error message, e.g. wrong password / host unreachable), or `error` if
   the driver isn't installed.

Credentials entered here are **never saved** — they're sent once to the
`/api/connectors/<id>/test-live` endpoint, used for that single connection
attempt, and discarded.

### Don't have a real data source to test against?
You can spin up a free local one with Docker, e.g. for PostgreSQL:
```bash
docker run --name test-postgres -e POSTGRES_PASSWORD=test123 -p 5432:5432 -d postgres
```
Then in the live test form use: host `localhost`, port `5432`, database
`postgres`, user `postgres`, password `test123`.

## Extending later
- Swap `agent.py`'s rule-based parser for a real LLM call (OpenAI/Anthropic)
  that returns the same JSON spec — the rest of the pipeline stays the same.
- Swap `storage.py`'s in-memory store for a real database.
- Replace the simulated connection test with an actual connection attempt
  using real credentials.
